# R027：基于滚动收益预测的训练卡推理切换决策

状态：已实现可选原型，正在开发验证，尚未确认性能收益。 记录日期：2026-10-20（America/Vancouver）。 归属：M2 调度机制；M1 提供显存可行性，M3
提供权重发布与版本就绪保证。

## 解决的问题

训练每次结束后都把共享卡切回推理，可能付出快照导出、权重加载、显存切换及再次恢复训练的成本，却只获得很短的推理窗口。提高推理时间占比本身不代表训练总耗时缩短。

## 主要思路

每次训练结束时比较两个方案：保持训练就绪，或切回推理。使用最近三个已完成批次的滚动窗口；不足三个时有多少用多少。根据当前生成进度、历史长度分布、排队情况和批次所需回答数估计剩余工作，不使用事后才能知道的最终长度。同一道题全部回答收齐的约束、在途请求及
off-policy 限制均需计入。

收益 = 不切换时预计关键路径完成时间 − 切换时预计关键路径完成时间。

切换方案应包括未被重叠隐藏的发布、恢复和计算竞争成本，以及增加推理能力带来的服务时间缩短。预期收益超过不确定性余量才切换。记录两个方案的预测、样本量和决策理由，避免重复扣除已重叠成本。样本不足或过时必须有明确保守回退，不能永久关闭共享推理。

吞吐预测要区分并发数、可用引擎数、是否与训练重叠，不能直接把共享卡独立吞吐加到固定卡吞吐上。跳过切换后，旧权重不能重新接收不兼容版本的请求；再次开放前必须完成必要更新。

## 难点与修改位置

先修复增量显存预算与交接计时，避免错误历史数据污染预测。预计涉及
`areal/trainer/colocation_memory.py`、`areal/trainer/rl_trainer.py`、`areal/infra/controller/rollout_controller.py`
及滚动窗口统计。绕过快照或发布前，需明确跳过版本及待更新权重的生命周期。

## 验证与收益

预算和计时修复在对照两组保持相同，单独比较每次切回与收益感知切回。首个条件为图模式、FSDP、两卡、96题、每题6回答、16题并发、6批、off-policy
2；增加推理充足、训练主导、最后批次长尾及历史不足场景。记录总耗时、批次收齐、tokens、有效推理窗口、切换成本、跳过次数和预测误差。开发阶段复用引擎加快测试，正式确认独立启动。目前不声称已有收益。

## 动机数据

[预算与计时修复实验](../experiments/2026-10-20-incremental-budget-timing.zh.md)：两轮共享均在6批允许推理重叠，但仍慢于固定，每轮约20秒等待上次发布收尾。这支持研究切换收益判断，不代表R027已有收益。

## 2026-10-20 原型实现

`AREAL_PROFIT_AWARE_RETURN=1`启用R027，验证期间默认关闭。`AREAL_RETURN_MARGIN_SECONDS`为要求的预测收益，默认0秒。

控制器在训练完成后冻结因果观测。新增`areal/infra/profit_return.py`结合最近三批的回答长度和并发服务速度、当前完整问题组及最多三次实测返回/恢复成本，比较固定卡独立完成与增加延迟就绪的共享卡两种情况。固定卡正在执行的请求保留原位置。数据不足时正常返回以采样；下一批已收齐时不返回。判断以`inference_return_decision`记录。

判断发生在固定卡HCCL发布前。不返回时不创建共享快照，不切换内存、不加载共享模型、不启动再均衡；固定推理卡仍更新最新权重。独立的保持训练状态标志阻止通用resume和训练期间推理错误使用旧权重，后续最新权重加载确认后才解除。评估强制正常发布；末批逻辑不变。原卡保留暂停请求模式在不返回推理时先执行强制撤离，不再强制返回推理。

当前预测采用条件平均剩余长度，再求问题组完成时间，尚未对多回答最大值做分布采样；恢复成本也暂按收齐后的串行成本估计。这些是待验证近似。需记录预测误差和负例，不能将利用率或生成token量不同当作性能收益。

开发实验目录：`/root/areal-development/r027-profit-return-20261020/`。两轮复用vLLM的固定/共享对照保持96题、每题6回答、16题并发、6批、FSDP、图模式、offpolicy=2。与bench新默认32题/批、8回答/题分开。最终正式确认需独立启动引擎。

## 已确认规则：决定保持训练状态后，必须迁走全部暂停请求

记录日期：2026-10-20（America/Vancouver），来自用户明确要求。本规则替代此前“再判断迁移是否合算”的建议，以及原型中“保留暂停请求时强制返回推理”的保底方案。

必须分开两个决策：

1. R027判断训练卡是否值得返回推理。
1. 一旦决定**保持训练状态、不返回推理**，该卡上的**全部暂停请求都必须迁走**。不再使用R001的正收益、剩余长度、探索次数、累计事务时间或负载均衡阈值筛选。不能因为某个请求迁移昂贵就把它留在原卡，也不能仅以迁移成本为理由推翻已作出的不切换决定。

传输方式按版本处理：

| 条件                                 | 执行规则                                                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| 权重版本一致，KV布局兼容且可安全导出 | 迁移请求状态及KV，在固定推理实例继续。                                                                   |
| 权重版本不一致                       | 不迁移、不导入旧KV。迁移原始prompt、已生成token前缀及剩余生成状态，由目标权重重新prefill建立KV，再继续。 |
| 同版本但KV无法安全导出或导入         | 回退到token前缀重算，并记录技术原因；不能无限期遗留暂停请求。                                            |
| 目标当前忙或即时容量不足             | 在固定推理容量侧排队/背压。这是可执行性约束，不是收益否决。                                              |
| 传输结果不明确                       | 保持单一所有者并核实/报告失败，不能丢弃、重复执行或虚报成功。                                            |

跨版本继续生成不会重算先前已经生成的token。必须保留原token的log-prob和版本信息，新token记录实际目标版本，并保留既有off-policy约束。因此它不等价于整个回答都由新版生成；版本不同不得复用旧KV。

实现应先关闭源卡准入、确认在途执行停止、登记完整待迁移集合。源端执行所有权的释放必须有已确认且可恢复的交接保障。KV暂存成功不等于已经导入，需分别记录暂存、源端中止、目标接续和`import_applied`。权重发布顺序与过期KV票据清理也需协调。

### 与R001可选再均衡的区别

R001是为改善负载而可选地搬移工作，成本不合算可以不搬。R027这里的迁移是卡退出推理后的完成性义务：遗留暂停请求可能让一道题乃至整个批次永远无法收齐。因此优先保证完成性和所有权，成本只用于观测分析，不作为第二次准入门槛。

### 实现与证据状态

当前代码已实现暂停态同版本 KV 导出、反向通道、逐请求版本锁定和跨版本前缀重算。此前冻结的 R027 对照没有包含这条新路径；实机验证状态与性能结论需要分别记录。

验证应覆盖：全部暂停请求迁出、混合版本、目标队列已满、多回答问题组收齐、同版本KV导入、版本不同后的前缀重算、发布竞态、部分传输失败，以及无遗留/重复请求。记录迁出/剩余数量、传输方式、源/目标版本、字节数、重算token量、耗时和批次完成结果；保留无收益与失败案例供论文讨论。

## 暂停请求迁移的最新实现与边界（2026-10-20）

本节记录从旧版强制返回保护到完整撤离协议的实现变化。R027
决定训练卡不返回推理后，必须迁走该卡的全部暂停请求，不再应用收益、探测次数、交易时间或长短请求筛选。迁移成本可以记录，但不能作为遗留请求的理由。

### 同版本：直接迁移 KV

先关闭源卡准入并确认原生暂停，再逐请求导出。根据实际存储位置，从 HBM 映射页或 DRAM 中的锁页备份读取每个 KV 块，按张量和块顺序装入有界 HBM
传输缓冲区。不会恢复整个 KV 池，不会读取已解除映射的地址，也不会在暂存时删除源备份。保留暂停模式会初始化共享卡到固定推理卡的反向 HCCL 通道。

目标版本必须与源请求租约的真实版本相同，不能用训练器的全局版本代替。导出前锁定目标版本，直到原生导入或重算确认后才解锁；仅获得路由租约不代表 KV 已导入。所有 TP
成员都通过准备检查后才能进入 HCCL；任何一张卡拒绝准备，都不能让其他卡先进入集合通信。

先传输并登记目标
ticket，再中止源卡上对应的精确请求尝试，源租约随中止响应释放。目标卡满载时排队。若发布权重正在关闭目标准入，仍须允许已经锁定的迁入请求进入，否则“等待导入”和“关闭准入”会互相死锁。每次只暂存一个请求，观察
`import_applied` 或原生重算回退确认后再处理下一个；全部处理后再清理源卡保留的 KV 和备份。

### 不同版本：迁移请求，重建 KV

版本不同时不传输或复用 KV，而是迁移 prompt、已经生成的 token 前缀和剩余生成状态，在目标权重下通过 prefill 重建 KV，再继续生成。KV
包含由原权重计算的中间激活；形状相同不代表内容可跨版本复用。

保留旧 token 的 logprob 与版本标签，新后缀标注目标实际版本，继续遵守既有 off-policy
语义。这不是“整个回答都由新模型生成”，也不保证与单版本生成相同。若要求整段回答严格使用同一版本，需要保留旧模型或重新生成完整回答，不能暗中将混合版本续跑当成单版本结果。

### 技术限制与回退

每个 TP 成员的暂存载荷上限仍为 64 MiB，并保留实际显存安全检查。超大请求、无法稳定导出的请求、已抢占且不具备可导出 KV
的请求、不支持的采样参数或暂存空间不足，采用前缀重算，不能被遗留在暂停卡上。目前没有实现大请求的分块 KV 传输。要求相同 TP、兼容的全注意力布局以及 PP=1，不等于
R026 跨 TP 迁移。HCCL 或中止结果不明确时必须报错并停止，不得推测成功后重复执行。

代码涉及
`dynamic_kv.py`、`kv_handoff.py`、`areal_vllm_server.py`、`request_router.py`、`kv_rebalance.py`
和 rollout controller。单元测试覆盖混合 HBM/DRAM 字节一致性、目标满载、版本锁定、跨版本回退、多种请求混合撤离以及 TP 成员准备失败。NPU
验证证据保存在
`/root/areal-development/retained-kv-20261020/`，应以实际结果文件区分实现完成与实机验证完成。本扩展首先保证正确性与请求可完成性，不能在没有实验的情况下宣称性能收益。

### 实机验证结果

图模式、TP=1 的原卡暂停迁移已收到原生 `import_applied`：256 个输出 token 与不中断的确定性生成完全一致，logprob 最大误差为
0.0。独立的 NPU 内存测试从混合 HBM/DRAM 备份复制 3 MiB，逐字节一致，源始终暂停，重新映射页数为 0。相关回归测试共 128
项通过。[验证证据](../experiments/evidence/r027-retained-20261020/summary.json)。

内存测试与请求续跑测试是分别执行的，不是完整 RL 性能实验。2026-10-21 补做的图模式 TP=2 测试也确认 `import_applied`，256 个输出
token 完全一致，logprob 最大误差为
0。[TP=2 证据](../experiments/evidence/r027-retained-tp2-20261021/result.json)。这验证了一对相同 TP
的实例，不代表任意实例数或跨机器传输均已验证。跨版本路由有单元测试覆盖，不代表允许跨版本复用 KV。

## 训练常驻预算实验（2026-10-21）

决定不返回推理后，下一批训练也应避免不必要的分配器缓存清理。常驻快速路径仍检查显存预算。实验开关 `AREAL_RESIDENT_BUDGET=1`
只抵扣经验证可复用的反向传播存储，以及当前设备、当前流上完全空闲、不可扩展的默认池段。默认池抵扣暂限单 rank
训练；通信流的复用尚未验证。优化器增长、权重发布、恢复空间及安全余量仍单独计入。如果训练存储已解除映射或卸载，不能走此快捷路径；预算不足则回到原有回收流程。

这并不等于将所有 reserved
显存都当成可用空间。快照字段不明、其他流、活跃分配、私有池及部分空闲段均不获得默认池抵扣。同时独立检查设备物理预算，避免抵扣掩盖超预算。性能与正确性验证完成前，该开关保持实验性质。两组均保留模型保存；新增计时拆分
CPU 状态收集、类型转换和序列化，不更改保存内容。

开发及正式结果见[训练常驻实验记录](../experiments/2026-10-21-r027-resident-training.zh.md)，其中保留未取得稳定收益的方案。

## 默认启用（2026-10-21）

两次独立启动对照均获正收益后，返回推理收益决策和常驻缓存预算改为默认启用。Benchmark 及 coverage
的共享组显式开启两项，固定组显式关闭。原有安全检查及默认池抵扣限单 rank 的限制保留。运行环境中显式设为 `0`
可关闭相应机制。历史实验中的“显式启用”描述的是实验当时的配置。
