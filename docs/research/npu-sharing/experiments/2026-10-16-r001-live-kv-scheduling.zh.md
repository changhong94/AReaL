# R001 在线 KV 调度验证 — 2026-10-16

[English](2026-10-16-r001-live-kv-scheduling.md)

## 结论

已实现 TP=1 的真实 KV 迁移路径和可选的成本感知调度器。但本次六批算术 RL 对照**没有证明运行中请求的 KV 迁移能带来额外加速**：两种并发规模均未实际迁移
KV。 功能仍为实验性质，默认关闭。

## 工作量与对照条件

- Qwen2.5-1.5B-Instruct、FSDP、两张 Ascend NPU。
- GSM8K 共 96 题，每题 6 个回答，每批 16 题，共 6 批、1 epoch。 最大回答长度 1024，`max_head_offpolicyness=2`。
- 并发题数分别为 16 和 32；每个引擎的原生序列容量按 `max(64, 并发题数×4)` 设置，分别为 64 和 128。
- 每一对对照采用相同显存预算、传输初始化、预测器、日志、模型、数据及配置。 内部环境变量 `AREAL_KV_REBALANCE_EXECUTE` 分别为 0（只记录方案）和
  1（允许执行）。 两组都保留原有排队请求调度。
- 耗时仅为训练循环，不含模型初始化和退出。

| 16       | 不执行，对照组   |        162.360 |      576 |     135945 |         0 |
| 16       | 允许执行         |        150.860 |      576 |     136471 |         0 |

由于没有发生 KV 迁移，上述时间差不能归因于迁移。16 题组还说明短实验中的长尾与调度波动 不容忽略；32 题组只相差约 0.34
秒。每种设置仅一对测试，不能证明统计意义上的不退化， 更不能保证其他场景都没有负收益。

16 题两组使用相同的、修正快照时间差之前的预测器版本，其中三次恢复因快照时间差跳过规划。 用修正后的代码回放五次保存的快照，仍然全部选择零迁移。32
题两组实际运行了修正版本， 代码哈希保存在证据中。后续分析时不能混淆这两个代码版本。

## 为什么增加请求后仍没有迁移收益

存在路由排队请求时，恢复的卡优先接收这些请求。没有这种工作时，预测器才扣除传输、 所有权切换、规划和保守的工作进程阻塞成本，判断是否能缩短完成时间。 在上下文长度桶 512
中，固定推理引擎的解码步平均耗时，在并发桶 32、64、128 下分别为 50.854、53.283、55.846
毫秒。因此，分走一部分请求并不会按比例缩短剩余请求的自回归生成时间。 这些是汇总观测样本，不是严格控制并发变量的微基准。

还用 32 题组的真实快照，将单次迁移数量上限从 16 放宽到 64、128 做离线敏感性检查， 依然没有选择迁移。因此，至少这些决策并非仅仅受迁移数量上限限制。
这不能代替对其他模型或长上下文负载的实测。

## 功能验证与保护条件

真实 vLLM 续跑验证中，在已经生成 34 个 token 后，导入 91 个已计算 KV token（3.5 MiB）。 最终 256 个贪心生成 token
与不中断的基线完全一致，logprob 最大差为 0。 源端打包约 11.568 毫秒，源端 HCCL 约 5.073 毫秒。首个冻结响应事件至目标端导入事件约 125 毫秒；
这不是纯传输时间，也不是完整协调器耗时。

实现保留版本及租约保护、原生 token/block 校验、按 KV 块取整的目标后续容量预算、 明确的导入确认，以及训练即将开始时在终止源请求之前撤销迁移的机制。
已均衡和无预计收益的场景不迁移；状态不明的异常采取停止相关路径的方式处理。 这些措施降低风险，并不是所有场景零回退的保证。

最新相关回归测试 **111 项通过**。独立的单请求 RL 强制集成检查也已通过，详见下方。 它绕过收益门槛，只验证路径，不能作为性能收益证据。

## 完整 RL 路由集成结果

独立检查成功完成两批和全部 192 个回答。一个运行中请求通过原有 RL 客户端及路由自动续跑， 迁移了 331 个已计算 KV token（10.5 MiB），目标端明确记录
`import_applied`。 从规划开始到确认的协调器耗时为 0.272716 秒，不含此前的快照采集。 打包约 15.250 毫秒；源端 HCCL 约 1.550
毫秒，目标端 HCCL 含等待对端约 44.138 毫秒。 两个通信区间重叠，不能相加。

收益覆盖只存在于独立工作区的冻结源码副本，代码库中的收益门槛没有绕过。
[集成证据及明确的源码覆盖记录](evidence/r001-kv-scheduling-20261016/rl-integration.json)
保留了实验性质和哈希。进程退出码为 0。

根据这次实测，代码库将初始单请求迁移成本从 0.1 秒提高为 0.3 秒；后续观测到更高成本时继续提高。 上面的在线对照仍使用原先 0.1
秒初值，不能把后续的保守调整写成新测得的加速。 0.273 秒包含协调及规划，也不能称为纯链路传输耗时。

最终 0.3 秒成本初值也回放了保存的十次 16/32 题并发恢复快照，依然全部选择零迁移。

项协调器及规划器定向测试通过。
