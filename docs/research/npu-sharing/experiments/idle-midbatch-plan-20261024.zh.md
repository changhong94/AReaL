# R030 批内扩展：正确性与六批对比结果

完成日期：2026-10-24（电脑本地时区 America/Vancouver）。本次为复用 vLLM 的单轮开发实验，不是独立启动的正式统计结论。

## 正确性

分段重新打包改变了计算布局，冻结输入整批梯度误差曾为 9.96%。保留原始完整微批计划后降到 1.3121%；最终完整 RL 验证为 1.2033%，通过原有 2% 门槛，9
次 rank 级完整状态导入校验通过。另外修复了回收后驻留预算不再扣除有效缓存的误拒绝，改为重新读取分配器证据。相关测试通过：22 项梯度/计划/控制器测试，31
项内存/计划测试。未放宽安全门槛。

## 性能

Code RL、FSDP、图模式推理、两卡、6 批、每批 32 题、每题 8 回答、题并发 16、评分并发
16、offpolicy=1。固定组保持原路径，共享组启用批内扩展。计时关闭完整梯度重算和逐字节校验，保留状态元数据检查。

| 指标                     |      固定 |      共享 |
| ------------------------ | --------: | --------: |
| RL 循环                  | 458.79 秒 | 496.32 秒 |
| PPO 区间（含嵌套切入）   | 290.21 秒 | 267.26 秒 |
| PPO 区间（扣除嵌套切入） | 290.21 秒 | 237.42 秒 |
| 全部切入和返回           |      0 秒 |  68.21 秒 |
| 训练器初始化             | 178.77 秒 | 309.30 秒 |
| 生成 token 数            |   361,923 |   361,241 |

共享总耗时增加 **37.53 秒，慢 8.18%**。扣除嵌套交接后的 PPO 区间节省 52.79 秒，不足以覆盖 68.21 秒切换及其它开销（含 20.15
秒等待上一轮后台收尾）。区间有嵌套，不可把全部切换再加到原始 PPO 时间上；PPO 区间含主机/RPC 开销，不是纯算子时间。共享 token 少
0.19%，但回答内容仍不同，不能视为完全相同训练输入的因果实验。

B1、B6 从批次入口使用双卡；B2–B5 分别在完成 34、68、70、67 个回答后切为双卡，处理剩余回答。切入分别 7.90、7.34、7.28、7.32 秒，返回各约
5.3–5.4 秒。没有沙箱上传重试。计时轮 18 次 rank 级状态导入使用元数据检查，未执行梯度诊断重算。批内扩展保持 `AREAL_IDLE_MID_BATCH=1`
可选，不作为性能更好的默认值。
